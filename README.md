# 討論卓 — Debate Prompt & Record

議題をひとつ投げると、4人の論者と1名の司会が討論するプロンプトを生成し、
**その討論結果を構造化して記録・可視化する**、完全ローカルの個人ツール。
決まらなかったことは、そのまま**続きの議論として同じ記録に積み増せる**。

会議のファシリテーションを任されたときに、
「どんな意見が出るか」「どこで揉めるか」「何と返すか」を事前に洗い出して持ち込むために作った。

- ビルド不要・依存ゼロ・サーバー不要・アカウント不要
- ライト／ダーク切り替え付き（初期値は OS の設定に追従）
- データはブラウザの localStorage にだけ保存され、外に出ない
- `index.html` をブラウザで開くだけで動く（`file://` でも可）
- PWA。ホーム画面に追加すればアプリとして開き、オフラインでも全画面が動く

---

## 使い方（4ステップ）

```
① compose.html   モードとカテゴリを選び議題を入力 → プロンプトを生成 → コピー
② ChatGPT        貼り付けて議論させる（4名 × 2〜5ラウンド）
③ import.html    構造化プロンプトをコピー → 同じチャットに投げる → 返ってきた JSON を貼る
④ record.html    論点マトリクス・議論フロー・想定問答集として保存・閲覧
⑤ record.html    残った項目を選んで「続き」を生成 → 返ってきた JSON を貼ると同じ記録に追記される
```

モード・議題・カテゴリ・ラウンド数は ① から ③ へ自動で引き継がれるので、入力は1回で済む。

---

## 7つのモード

卓の目的をタブで切り替える。同じ議題でも出てくるものが変わる。

| モード | 何をさせるか | 席 | ラウンドの流れ（標準） |
|---|---|---|---|
| **討論** DEBATE | 対立させて判断材料を出す | カテゴリごとの論者（14種 × 4名） | 立場表明 → 前提の破壊 → 修正と応酬 |
| **アイデア出し** IDEATE | 案を量産して選び抜く | 量産役／転用役／制約破壊役／現実化役 | 大量発散 → 掛け合わせ → 極端化 → 選別と具体化 |
| **思考の深掘り** DEEP | ひとつの問いを掘り下げる | 定義役／前提発掘役／機構解明役／反証役 | 問いの立て直し → 前提の掘り出し → 反証テスト |
| **学術討論** ACADEMIC | 証拠の強さで判定する | 概念の定義役／実証役／方法論の検査役／対抗仮説役 | 命題の定式化 → 証拠の提示 → 批判的吟味 → 対抗仮説 |
| **壁打ち** SOCRATIC | 1対1で問い返してもらう | 問い手（AI）／あなた（人間） | 現在地の確認 → 前提の掘り出し → 言語化と次の一歩 |
| **レッドチーム** REDTEAM | 失敗した前提で原因を洗う | 失敗の語り部／外部要因役／内部要因役／兆候役 | 事前検死 → 原因の分解 → 兆候と検知 → 防御と撤退線 |
| **関係者総当り** STAKE | 実際に関わる人の利害でぶつける | 自分で指定した4つの立場 | 利害の表明 → 衝突の可視化 → 交渉と条件 → 落としどころ |

- 討論以外は席が固定（関係者総当りだけは自分で指定する）。カテゴリは「議題の領域」としてプロンプトに渡る
- ラウンド数はどのモードも 2〜5。構成と解説はモードごとに切り替わる
- 結果はどのモードも同じ `debate-record/v1` に構造化されるので、記録・可視化・検索はそのまま使える

### 学術討論だけの約束ごと

このモードだけは、入力に書かれていない外部の知識（研究・データ）を持ち出させる。
そのため出典や数値の捏造が起きやすいので、プロンプト側で次を強制している。

- すべての根拠に水準ラベルを付ける — `[確立] [有力] [議論あり] [限定的] [理論] [要確認]`
- 出典を思い出せない場合は `[要確認]` とし、**著者名・刊行年を埋めさせない**
- 具体的な数値は `[要確認]` なしで書かせない
- 最後に **エビデンス台帳**（根拠・水準・研究の型・確かめる方法の表）を出させる
- 構造化すると、`[要確認]` の項目が `tasks`（裏取りリスト）に落ちる

台帳に載った項目は必ず自分で裏を取ること。このモードは「調べる方向を決めるための道具」であって、出典そのものの保証はしない。

### 壁打ちだけの約束ごと

このモードだけは **AI が最後まで進めきらない**。他のモードが「一人で全員分を演じきる」のに対し、
壁打ちは1問投げるたびに止まり、あなたが答えるのを待つ。

- 一度に問うのは1つだけ。答えるまで次へ進まない
- 答えたら要約して確認してから、次の1問が来る
- 助言・結論・励ましは書かせない（最後のまとめだけが例外）
- ラウンド数は「問いの段階数」として働く
- 記録上の席は 1＝問い手／2＝あなた の2つになる

移動中や寝る前など、5,000字を読む余裕がないときのためのモード。

### レッドチームと関係者総当りの使いどころ

- **レッドチーム** は、迷っていることではなく **すでに決めたこと** を入れる。「実行され、そして失敗した」という前提から逆算するので、案が固まっていないと空回りする。出口は撤退線の一覧（兆候・見張る人・打つ手・やめる線）。
- **関係者総当り** は、席をこちらで指定する。個人名より立場（直属の上司／会計担当／来られていない人）で書くほど代弁の精度が上がる。指定した席は端末に保存され、取り込み画面にも引き継がれる。出口は落としどころと、伝える順番。

## 続きの議論（未解決を持ち越す）

記録詳細の **「05 / Continue — まだ決まっていないことを、続けて詰める」** から。

```
① 残っている項目をチェックで選ぶ（未解決が上に並ぶ。合意済みも選べる）
② 続きのやり方を選ぶ  討論で詰める / アイデアを出す / 掘り下げる
③ 「続きの議論をさせる」プロンプトをコピー → ChatGPT へ
④ 「結果を追記用 JSON にする」プロンプトを同じチャットへ
⑤ 返ってきた JSON を貼って「この記録に追加する」
```

追記されるとき、記録には次のことが起きる。

- 選んだ論点の **状態・到達点・各論者の立場が更新される**（前の立場は上書き、到達点は積み上がる）
- 新しく出た論点・発言・リスク・アイデア・タスク・想定問答が **追加される**
- 発言のラウンド番号は前回の続きから振り直され、議論フロー図が右に伸びる
- 総括の見落とし・次の問いが足され、結論が変わった場合だけ差し替わる
- ヘッダに「続き N 回」、続きセクションに履歴（日付・やり方・扱った項目・到達点）が残る

**新しい記録は増えない。** ひとつの議題の思考が1件の記録に積み上がっていく。
前回の内容が消えることはなく、追記だけが行われる。

### ③ で JSON が途中で切れたら

取り込み画面の「PART 1（論点・発言）」「PART 2（リスク〜総括）」に切り替えて2回に分けて出させ、
それぞれを「解析して追加」で読み込む。自動でマージされる。

前後に説明文が付いていても、コードブロックのまま貼っても、末尾カンマや全角引用符が混じっていても、
取り込み側で自動修復する。

## 画面

| ページ | 役割 |
|---|---|
| `index.html` | ダッシュボード。記録一覧・全文検索・タグ絞り込み・統計・バックアップ |
| `compose.html` | 議題設計とプロンプト生成（7モード × 14カテゴリ × 1〜4席 × 2〜5ラウンド） |
| `import.html` | 構造化プロンプト生成と JSON 取り込み |
| `record.html?id=…` | 記録詳細。下記4つの可視化と、続きの議論の生成・追記 |

### 記録詳細で見られるもの

1. **論点 × 論者マトリクス** — どの論点で誰が賛成／反対／条件付きか。丸の濃さが論の強さ、左の点が重要度。会議前に一番効く画面
2. **議論フロー図** — 横がラウンド、縦が論者。赤い破線が「誰が誰の前提を潰したか」
3. **リスク／アイデアの3×3マトリクス** — リスクは「起こりやすさ × 影響」、アイデアは「効果 × 労力」
4. **想定問答集** — 論点ごとに「出そうな意見／言いそうな立場／こちらの返し／根拠／無視した場合」。印刷するとこのセクションだけが紙面に出る（テーマに関わらず白地）

ほかに、決定事項・タスク（チェック可）・未解決論点・続きの議論・司会の総括。

## 表示テーマ

右上のボタンで **自動 → ダーク → ライト** を切り替える。選んだ設定はこの端末に保存され、全ページで共有される。

- **自動** は OS のダークモード設定に追従する（設定を変えると即座に反映）
- 色はすべて CSS 変数（`assets/tokens.css` の `:root`）で定義してあり、SVG の可視化もテーマ変更時に描き直される
- 印刷だけはテーマに関わらず白地・黒文字で出る

---

## データについて

- 保存先はブラウザの localStorage（`debate-app:` プレフィックス）
- **ブラウザの閲覧データを削除すると記録も消える**。ダッシュボード下部の「JSON で書き出す」で定期的に控えを取ること
- 別の端末で見たいときも、書き出した JSON を持っていって「ファイルから読み込む」
- 記録1件あたり 10〜20KB 程度。上限の目安は 5MB 前後

## PWA として使う

HTTPS（または `localhost`）で配信されているときだけ Service Worker が動く。`file://` で開いた場合は登録をスキップし、これまで通りの静的ページとして動作する。

- **入れ方** — ブラウザのメニューから「アプリをインストール」、または画面下部に出るバーの「追加する」。iOS Safari は共有メニューの「ホーム画面に追加」
- **オフライン** — 初回アクセス時に全画面と assets を先読みするので、電波がなくても記録の閲覧・作成・取り込みまで一通り動く。記録はもともと localStorage にしかないので通信は不要
- **更新** — 新しい版を検知すると「新しい版があります」と出る。「更新する」で即座に切り替わる
- **ショートカット** — アイコンの長押し／右クリックから「新しい討論をつくる」「討論を取り込む」へ直行できる

配信ファイルを差し替えたのに古い画面が出るときは、`sw.js` の `VERSION` を上げるとキャッシュが作り直される。

`assets/catalog.js` の `GROUPS` にカテゴリを追加すれば、自分の職場専用の卓（部長役・経理役・現場役・若手役など）を作れる。

## 記録フォーマット `debate-record/v1`

`assets/schema.js` が定義元。取り込み画面が生成するプロンプトにそのまま埋め込まれる。

```
meta        タイトル・モード・カテゴリ・ラウンド数・日付・タグ・参加者
issues      論点（重要度・状態・各論者の立場と強さ・未解決点・到達点）
moves       発言（ラウンド・論者・種別・要点・攻撃対象・撤回/修正/強化）
risks       リスク（起こりやすさ・影響・対策）
ideas       アイデア（効果・労力）
decisions   決定事項      tasks  タスク
objections  想定問答（会議で出そうな意見と返し）
summary     推奨案・理由・トレードオフ・見落とし・次の問い
_sessions   続きの履歴（回数・日付・やり方・扱った項目・到達点・追記件数）
```

## 追記フォーマット `debate-followup/v1`

続きの議論を既存の記録にマージするための差分。`DA.applyFollowup(rec, patch)` が適用する。

```
session         今回のやり方・ラウンド数・扱った項目・到達点
issue_updates   既存論点の更新（状態・到達点・残った未解決点・立場の変化）
new_issues      今回新しく生まれた論点
moves           今回の発言（round は今回内の 1〜n。取り込み時に前回の続きへずらされる）
risks / ideas / decisions / tasks / objections   今回追加された分だけ
summary_update  結論の差し替え（空なら据え置き）と、理由・見落とし・次の問いの追加
```

論点 ID の衝突、発言 ID の衝突、`targets` の参照は取り込み時に自動で付け替えられる。
記録そのもの（`debate-record`）を貼った場合は追記されず、取り込み画面へ誘導される。

## これから足せるもの

- **予測 vs 実際の突き合わせ** — 会議後に「出た／出なかった／想定外」を記録し、自分の読みの癖を蓄積する（スキーマの `objections.actual` は既に用意済み）
- ファシリ台本／時間配分付きアジェンダの生成
- 記録どうしの突き合わせ（同じ議題を別モードで回した結果を並べる）
- 全記録を横断して「繰り返し刺さる反対意見」を集計
- 続きの回ごとに、立場がどう動いたかの差分表示
